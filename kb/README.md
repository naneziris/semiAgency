# Knowledge base (workflow #8)

The local memory every other workflow reads from and writes to. Plain markdown and JSON, one folder per kind of thing, dated file names. GitHub Copilot reads it through the workspace; scripts keep it tidy. Nothing here is ever written by an M365 agent directly — handoffs come in through `inbox/` and `scripts/kb_ingest.py` routes them.

```
kb/
├── inbox/            drop handoffs here (see docs/handoff-format.md) → python scripts/kb_ingest.py
├── archive/          raw handoffs after ingest, never edited (redo a bad split from here)
├── calendar/         <date>.md          today's/tomorrow's events (from the Daily Exporter)
├── email/            <date>.md          the day's decision-needing emails, summarised (from the Daily Exporter)
├── triage/           <date>.md          your email triage: todos with urgency/effort/delegate + reply drafts (/triage-inbox)
│                     <date>.todos.json  the machine-read version → append_tasks.py → tracker
├── topics/<topic>/   profile.md         your interest profile for the topic (/interview-topic, /refine-topic)
│                     links/<date>.md    every link about the topic seen that day (from the Daily Exporter)
│                     links.md           GENERATED — all links ever, one table, newest first (kb_index.py)
│                     digests/<date>.md  the day's flagged items + the rest (/triage-topic)
├── people/<slug>/    <date>.md          1-1 prep summaries / reports (from the 1-1 Prep agent, or written by you)
│                     profile.md         optional: role, what they're working on, standing topics
├── briefs/           <date>.inputs.md   GENERATED by brief_collect.py — everything the brief needs, in one file
│                     <date>.md          the morning brief (/morning-brief)
├── meetings/         transcripts/write-ups handed off M365-side, waiting to become an engagement
├── notes/            anything else worth keeping
└── index.md          GENERATED — what's in here, newest first, with open counts
```

Conventions:

- Dates are `YYYY-MM-DD` in file names and `date:` headers. Newest wins when two files disagree.
- People slugs are the name you use, lower-cased, hyphens (`maria-k`). Same slug everywhere: calendar `with`, `people/`, tracker `owner`.
- Topic slugs are short and lower-case (`ai`, `platform-security`).
- Generated files say so in their first line and are safe to delete — they are rebuilt by `python scripts/kb_index.py`.
- Copilot may write under `triage/`, `topics/*/profile.md`, `topics/*/digests/`, `briefs/*.md`, `people/*/profile.md`. It never writes under `archive/`, `calendar/`, `email/`, `topics/*/links/` — those are evidence, like `engagements/*/inputs/`.
- Actions never live only in a markdown file. Anything you commit to goes through a `*.todos.json` / `tasks.json` and `append_tasks.py` into `tracker/actions.xlsx`, which is the single list of open actions across all workflows.
