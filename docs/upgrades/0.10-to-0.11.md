# Upgrade 0.10 → 0.11: the map, one area per flow

Nothing in D2P changes: no prompt, instruction, template or engagement script is touched. Only the map and one reference doc.

- `city/scene.jpg` + `city/hotspots.json`: a new painted island with one colour-coded area per flow (Central Agora, Proposal Acropolis, Deck Street, Notary Corner, Gate of Envoys, Observatory Hill, M365 Harbour, Construction Yard), one building per step, and four clickable piers in the harbour.
- `city/city.json`: restructured to match. Buildings gain `sub`, `mode` and `asks` ("Ask it" tables for the M365 agents). There are new `landmarks` (the piers). Journeys gain `area`, `audience`, `bring`, `get` and `time`. The Front Desk building (`picker: true`) shows every flow as a card.
- `scripts/build_city.py`: renders the above, adds an "I work in" filter, area labels and colours, and puts the guide panel on the side away from the route. **Output renamed `city.html` → `index.html`** so GitHub Pages serves it as the home page.
- `city/README.md`: new hotspot table, the v2 image prompt, and publishing on GitHub Pages (an optional Action that publishes only `index.html`).
- `docs/use-cases-and-flows.md`: every flow with when / input / output, every agent and prompt use case, and the UX notes behind this map.

## Getting the files: from a ZIP, never over your folder

On GitHub: **Code → Download ZIP**. **Unzip it somewhere else** (e.g. `Downloads/semiAgency-main/`), never into your working folder. The ZIP has the public versions of `tracker/actions.csv`, `brand/voice.md` and the READMEs; unzipping over your folder would replace your data with those. Nothing from the ZIP gets copied except the files named below.

Before anything else, mark the point you can return to:

```
git status                      # must be clean; commit first if not
git tag pre-0.11
```

Undo at any point: `git reset --hard pre-0.11`. Files that step 3 below creates but that don't exist at that tag are removed with `git clean -fd city docs`. Read the dry run `git clean -nd city docs` first.

## Apply (5 minutes, in the semiAgency folder on the corporate machine)

1. Check you are on 0.10: `VERSION` says `0.10.0`. Older? Apply the earlier notes first, in order.
2. Commit or stash anything open (`git status` clean).
3. If you came from 0.9 with the same ZIP, the files are already there. Otherwise copy the whole `docs/upgrades/` folder from the unzipped folder over yours. Don't open the patch in an editor: saving it can change its line endings. Then:

```
git apply --check --binary docs/upgrades/upgrade-0.10-to-0.11.patch
git apply --binary docs/upgrades/upgrade-0.10-to-0.11.patch
git rm city.html
python scripts/build_city.py --check
```

4. Set `VERSION` to `0.11.0`, open `index.html`, commit.

If `--check` fails on `README.md` or `city/README.md` because you edited them locally, use `git apply --3way --binary …` and resolve the conflict. Everything else in the patch is map-only.

The patch deliberately leaves out the generated HTML: step 3 rebuilds it from your own repo, with your `redact` map applied.

## If `git apply --check` says "patch does not apply"

This is almost always line endings on Windows (`git config core.autocrlf` is `true`). Try in this order:

1. `git apply --check --binary --ignore-whitespace docs/upgrades/upgrade-0.10-to-0.11.patch`. If that passes, apply with the same flags.
2. If it still fails, copy files instead. Take exactly these from the unzipped folder, overwriting yours: `city/city.json`, `city/hotspots.json`, `city/scene.jpg`, `city/README.md`, `scripts/build_city.py`, `docs/use-cases-and-flows.md`. None of them holds corporate data, and 0.10 installs don't edit them. For the root `README.md`, don't copy it: in the heading "The map" and in the line below it, replace `city.html` with `index.html`. Then `git rm city.html` and continue with `build_city.py --check`.

Either way, `git diff --stat pre-0.11` before committing must list only the files above plus `README.md`, `VERSION`, `city.html` (deleted), `index.html` and `docs/upgrades/`. Anything else in that list means something was copied that shouldn't have been.
