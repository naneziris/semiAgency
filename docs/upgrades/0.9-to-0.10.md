# Upgrade 0.9 → 0.10: honest value in options, Fit Finder, bench, the map

## What changes

**D2P (affects your next proposal):**
- `.github/instructions/options.instructions.md`, `templates/options.md`, `.github/prompts/options.prompt.md`: every option gets a `**Value**` block right after `**Summary**`, with two lines: `New capability:` (or `none — efficiency only`) and `Saved effort:`. The `## Comparison` table gets a `new capability` row. Saved effort must never be presented as a new capability.
- `.github/instructions/proposal.instructions.md`: `## What we propose` opens with the new capability; saved effort follows as a separate sentence.
- `.github/agents/critic.agent.md`: the critic adds `## Value claims`, which quotes every sentence that inflates saved effort into a capability.
- `scripts/validate.py` (built on your machine, not shipped): must accept and require the new `**Value**` block. See step 5.

**M365:** `m365/07-fit-finder-agent.md` (a shared agent that turns an AI idea into a brief for a team), plus the sheet 7 row and "Shared agents" section in `m365/README.md`.

**New, independent of D2P:**
- `bench/`: a personal model benchmark kit, copied into an empty workspace to use (`bench/README.md`).
- The map: `city/` and `scripts/build_city.py` generate `city.html` (in 0.11 it becomes `index.html`).

## Apply from a GitHub ZIP (15 minutes)

1. On GitHub: **Code → Download ZIP**. Unzip it **somewhere else** (e.g. `Downloads/semiAgency-main/`), never into your working folder. The ZIP has the public `tracker/actions.csv`, `brand/voice.md` and READMEs, and unzipping over your folder would replace your data with them.
2. In your corporate folder: `VERSION` says `0.9.0`, `git status` is clean (commit first if not), then `git tag pre-0.10`. Undo at any point: `git reset --hard pre-0.10`, and `git clean -fd bench city` for new files (dry run first: `git clean -nd bench city`).
3. Copy the whole `docs/upgrades/` folder from the unzipped folder over yours. It only holds these notes and the patches. Don't open a `.patch` in an editor, because saving can change its line endings.
4. Apply:

```
git apply --check --binary docs/upgrades/upgrade-0.9-to-0.10.patch
git apply --binary docs/upgrades/upgrade-0.9-to-0.10.patch
python scripts/build_city.py --check
```

   A warning about "trailing whitespace" in `templates/options.md` is expected: the `New capability: ` and `Saved effort: ` lines end with a space on purpose.

5. Update your `validate.py`. Copilot Chat, agent mode:

```
In scripts/validate.py, update the options.md schema to match .github/instructions/options.instructions.md: each `## O<n>` option must contain a `**Value**` block directly after `**Summary**`, with a line starting `New capability:` (non-empty; `none — efficiency only` is valid) and a line starting `Saved effort:`; the `## Comparison` table must have a row `new capability`. Report a missing block as an error naming the option. Keep stdlib only, change nothing else, then run python scripts/selftest_all.py and fix only what this change broke.
```

   An `options.md` from an engagement you started before 0.10 will now fail validation. Add the `**Value**` lines by hand, or re-run `/options` if you haven't passed G2 yet.

6. `git diff --stat pre-0.10` lists the files above, `bench/`, `city/`, `city.html`, `scripts/build_city.py`, `scripts/validate.py`, `README.md`, `VERSION` (now `0.10.0`) and `docs/upgrades/`. Nothing under `engagements/`, `tracker/` or `brand/`. Commit.

Then continue with `0.10-to-0.11.md`. The `docs/upgrades/` folder you copied in step 3 already contains it.

## If `git apply --check` says "patch does not apply"

This is usually Windows line endings (`git config core.autocrlf` is `true`). Retry with `--ignore-whitespace` added to both commands. If a file still fails because you edited it locally (most likely `README.md` or `m365/README.md`), use `git apply --3way --binary …` and resolve the conflict markers. Git only knows the original version of a file if yours matched 0.9 exactly; otherwise merge that one file by hand from the unzipped folder.
