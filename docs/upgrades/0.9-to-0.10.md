# Upgrade 0.9 → 0.10: `bench/` — personal model benchmark kit

Nothing in D2P changes. New top-level folder `bench/`, self-contained, not wired into `status.py` or the engagements: it is a kit colleagues copy into an empty workspace to benchmark the models in their Copilot picker on their own failed tasks (`bench/README.md`).

- `bench/.github/prompts/`: `/bench-setup` (interview → `cases/`), `/bench-run` (one case, currently selected model → `runs/`), `/bench-feedback` (two outputs side by side → `grading/checks.md`), `/bench-judge` (`@judge` grades pending runs → `results/`).
- `bench/.github/agents/judge.agent.md`: read-only grader, PASS/FAIL with quoted evidence, one judge model for the whole benchmark.
- `bench/scripts/`: `bench_new_run.py` (run-file allocation for chat mode), `bench_cli.py` (Copilot CLI runner and judge: `--models`, `--repeat`, `--judge --judge-model`, `--dry-run`), `bench_report.py` (`index.html` matrix + side-by-side; `--pending`). Stdlib only, shipped as files (tested with synthetic runs).
- `bench/cases/_example/`: one complete case (exec summary) showing the target shape; `bench/models.txt`: model ids for the CLI.

To apply: copy the `bench/` folder; add the README section "Also in this repo: bench/"; set `VERSION` to 0.10.0.

## Also in 0.10: `city.html` — the shareable map

- `city/city.json`: the manifest — districts, one entry per building (pitch, steps with copy blocks, the prompts / agents / docs it contains), the journeys ("I want to…" with a when-to-use and numbered stops), the `redact` map and the `never_embed` list.
- `scripts/build_city.py`: generates `city.html` (self-contained, no network, ~130 KB) from the manifest and the real prompt/sheet files; scans `.github/prompts`, `.github/agents`, `m365/`, `agents/` and top-level kits for anything unclaimed and places it in "New Arrivals"; `--check` exits 1 in that case. Stdlib only.
- `city.html`: the output, committed so it can be sent as is. Rebuild after every change to prompts, sheets or the manifest.
- Illustrated mode: drop `city/scene.jpg` + `city/hotspots.json` (traced with `city/hotspot-editor.html`) next to `city.json` and the same script renders the painted city with clickable hotspots; new features land on free lots automatically. `city/README.md` has the steps and the image prompt.
